# Технічне завдання

## PWA «Локальна мережа взаємодопомоги»

**Версія:** 1.0
**Тип:** Production-ready MVP / перша повна версія
**Frontend:** React + TypeScript + Vite + PWA
**Backend:** Django + Django REST Framework
**Database:** PostgreSQL + PostGIS
**Realtime:** Django Channels + WebSocket
**Background jobs:** Celery + Redis
**Push notifications:** Web Push API
**Storage:** S3-compatible object storage
**Maps:** MapLibre GL JS + OpenStreetMap-compatible tiles
**Deployment:** Docker Compose для local development, Docker/Kubernetes-compatible production deployment

---

# 1. Мета продукту

Створити локальну цифрову мережу взаємодопомоги, у якій люди можуть:

1. повідомити людей поблизу, що їм потрібна допомога;
2. отримати повідомлення про потребу в допомозі поруч;
3. запропонувати свою допомогу;
4. поспілкуватися з людиною;
5. отримати/надати допомогу;
6. подякувати після завершення;
7. поступово сформувати репутацію на основі реальної допомоги.

Основний принцип:

> **«Мені потрібна допомога → люди поруч отримують повідомлення → хтось може допомогти → допомога відбулася → людина дякує».**

Другий напрямок:

> **«Я можу допомогти → бачу релевантні запити поруч → реагую → допомагаю».**

Це НЕ класичний marketplace послуг.

У системі не повинно бути концепцій:

* «замовник»;
* «виконавець»;
* «замовлення»;
* обов'язкова оплата;
* обов'язкова комісія платформи.

Одна й та сама людина може бути як тим, хто просить допомоги, так і тим, хто допомагає.

# 2. Основна цінність

Користувач не повинен думати:

> «Чи є тут потрібна мені послуга?»

Він повинен думати:

> «Мені потрібна допомога — чи є хтось поруч, хто може допомогти?»

Або:

> «Хтось поруч потребує допомоги — чи можу я зараз допомогти?»

# 3. Основні use cases

## 3.1. Автомобіль

* пробите колесо;
* розряджений акумулятор;
* потрібні дроти для прикурювання;
* потрібен компресор;
* потрібен домкрат;
* закінчилося пальне;
* потрібно витягнути автомобіль;
* потрібна допомога з буксируванням;
* ключі залишилися в автомобілі;
* дрібна технічна допомога.

## 3.2. Дім

* перенести важкий предмет;
* зібрати меблі;
* щось полагодити;
* потрібен інструмент;
* потрібно просвердлити отвір;
* допомогти з переїздом;
* потрібна фізична допомога.

## 3.3. Речі

* позичити інструмент;
* позичити предмет;
* передати предмет;
* забрати предмет;
* доставити предмет;
* знайти/повернути загублену річ.

## 3.4. Тварини

* загубилася тварина;
* знайдена тварина;
* потрібно перевезти тварину;
* потрібна допомога з пошуком.

## 3.5. Люди

* допомогти літній людині;
* допомогти донести речі;
* супроводити;
* допомогти людині, яка загубилася.

## 3.6. Район / локальна ситуація

* попередити людей про небезпеку;
* допомогти після негоди;
* знайти загублений предмет;
* локальна ситуація, де потрібна допомога.

## 3.7. Надзвичайні ситуації

Можливість створити запит з високою терміновістю.

При цьому система ОБОВ'ЯЗКОВО показує:

> Цей сервіс не замінює екстрені служби. У небезпечній або критичній ситуації телефонуйте 112 / 101 / 102 / 103.

# 11. Help Request model

Django model:

```python
class HelpRequest(models.Model):
    id = UUIDField(primary_key=True)

    author = ForeignKey(User)

    category = CharField(...)
    subcategory = CharField(null=True, blank=True)

    title = CharField(max_length=120)
    description = TextField(max_length=1000)

    location = PointField(
        geography=True,
        srid=4326,
    )

    location_accuracy = FloatField(null=True)

    urgency = CharField(...)

    reward_type = CharField(...)
    reward_amount = DecimalField(
        null=True,
        blank=True,
        max_digits=10,
        decimal_places=2,
    )

    status = CharField(...)

    created_at = DateTimeField()
    updated_at = DateTimeField()

    expires_at = DateTimeField()

    completed_at = DateTimeField(null=True)

    selected_helper = ForeignKey(
        User,
        null=True,
        blank=True,
    )
```

# 14. Геопошук

Використовувати PostGIS.

Приклад логіки:

```sql
ST_DWithin(
    location,
    user_location,
    radius_meters
)
```

Distance:

```sql
ST_Distance(
    location,
    user_location
)
```

Не використовувати Python loops для геопошуку.

Пошук повинен виконуватися на рівні PostgreSQL.

Створити необхідні spatial indexes.

# 24. Smart notifications

Не потрібно надсилати кожен запит усім користувачам міста.

При створенні HelpRequest:

1. знайти користувачів у потрібному radius;
2. відфільтрувати за category;
3. врахувати urgency;
4. врахувати notification preferences;
5. виключити автора;
6. виключити blocked users;
7. відправити push.

# 27. Notification anti-spam

Не відправляти одному користувачу необмежену кількість notifications.

Ввести rate limiting.

Наприклад:

```text
max 10 nearby-help notifications / hour
```

Для HIGH urgency допускається окрема логіка.

Також:

* не надсилати notification для вже закритого request;
* не надсилати автору;
* не надсилати користувачам, які вже відмовились;
* не надсилати blocked users;
* не надсилати після expiration.

```python
    help_request = ForeignKey(
        HelpRequest,
```
```python
        null=True,
        blank=True,

        Message,
        null=True,
        blank=True,
    )

    reason = CharField(...)

    description = TextField(
        max_length=1000,
        blank=True,
    )

    status = CharField(...)

    created_at = DateTimeField()
```

# 38. Blocking

User може заблокувати іншого користувача.

```python
class UserBlock(models.Model):
    blocker = ForeignKey(User)

    blocked = ForeignKey(User)

    created_at = DateTimeField()
```

Unique constraint:

```text
(blocker, blocked)
```

Blocked users:

* не бачать requests один одного;
* не отримують notifications;
* не можуть писати один одному;
* не можуть створювати interaction.

# 61. Business rules

## Rule 1

Не можна створити HelpRequest без valid location.

## Rule 2

Користувач не може відповідати на власний request.

## Rule 3

Не можна respond на:

```text
CANCELLED
COMPLETED
EXPIRED
```

## Rule 4

У request може бути тільки один selected helper.

## Rule 5

Після selection request переходить:

```text
ACTIVE → IN_PROGRESS
```

## Rule 6

Після completion:

```text
IN_PROGRESS → COMPLETED
```

## Rule 7

Complete може тільки автор request.

## Rule 8

ThankYou можна створити тільки після COMPLETED.

## Rule 9

ThankYou може створити тільки автор request для selected helper.

## Rule 10

Користувач не може створити більше одного active response на один request.


Вона знаходить:

# 66. Transactions

Critical operations виконувати в:

```python
transaction.atomic()
```

Особливо:

```text
select-helper

accept-response
```

При selection helper необхідно запобігти race condition.

Використати:

```python
select_for_update()
```

щоб два користувачі не могли одночасно стати selected helper.

# 109. Notification architecture

Не відправляти push synchronously в HTTP request.

Wrong:

```text
POST /help-request
    ↓
send 1000 pushes
    ↓
HTTP response
```

Correct:

```text
POST /help-request
    ↓
create request
    ↓
queue notification task
    ↓
HTTP response

Celery
    ↓
find users
    ↓
send pushes
```

# 149. Головний критерій успіху першої версії

Новий користувач повинен мати можливість:

**зареєструватися → дозволити location → створити запит → отримати відгук від людини поруч → поспілкуватися → отримати допомогу → завершити запит → подякувати.**

Інший користувач повинен мати можливість:

**зареєструватися → вибрати, з чим може допомагати → отримати push про проблему поруч → відкрити запит → запропонувати допомогу → поспілкуватися → допомогти → отримати подяку.**

Якщо ці два сценарії працюють швидко, безпечно та надійно — основна функціональність першої версії реалізована.
